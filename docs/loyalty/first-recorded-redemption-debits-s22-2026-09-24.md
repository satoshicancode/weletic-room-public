# S22 first recorded reward-debit accounts candidate — September 24, 2026

This is a **partial analytics implementation candidate**, not a successful-redemption or lifetime shopper cohort. It counts distinct currently retained Loyalty accounts with a negative `REDEEM_REWARD` ledger entry in each UTC month of an explicitly selected interval. An account is “first recorded” only when no earlier retained matching debit exists before the selected start or month; otherwise it is “repeat.” Several debits in one month count once. Quiet months appear as zero; counts are exact decimal strings.

The coverage marker `retained_reward_debit_accounts_only` is material. The debit is appended while remote reward issuance is still provisioning and can later be compensated, cancelled or refunded. It is not proof of successful issuance, discount use or economic cost. Missing pre-Weletic history, erased accounts and multiple accounts per shopper prevent a lifetime customer cohort. Both date endpoints are required; the selected range is capped at 366 UTC days. The report returns no account, shopper, order or discount identifier.

The reader uses the existing signed merchant gateway, actor-derived store scope and repeatable-read snapshot. The account-month candidate set excludes retained customer-redaction tombstones. The same privacy correction is applied to the existing S21 earning cohort; closed but non-redacted accounts remain eligible in both. The exact aggregate appears in owner CSV/JSON and EN/JA/VI screen copy. No table, writer or migration is added.
