## Execution rules and reusable test gates

- Work only from public main; preserve private legacy remotes read-only, unfinished
  import/video branches, failed evidence and user edits. Rebase no legacy feature
  wholesale without contract review.
- Use independent module switches and signed Shopify-first gateways. Preserve
  store ownership, installation generation, revision checks and exact arithmetic.
- **T1:** focused production-service/contract/component tests, adversarial review,
  Prisma validation where relevant, formatting, lint, types, builds and public CI.
- **T2:** isolated real SQL transactions/races, independent reconciliation and exact
  cleanup; mocked Shopify/Redis/email is explicitly labeled, not live proof.
- **T3:** named yamaxdev authentication, UI/worker/provider journey, EN/JA/VI,
  375px/keyboard/loading/error/permission/privacy checks and recorded cleanup.
- **T4:** deployed provider, supervision/recovery, backup/restore and privacy
  acceptance in the actual target environment. Local image boot is insufficient.
- A task is done only when its specified tests and exit condition pass. Financial
  values remain exact decimal strings; unknown history/currency/denominators are
  unavailable, never guessed. No simulated checkbox promotion.
