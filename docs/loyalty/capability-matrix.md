## Status definitions

- **Staging live-validated:** the stated capability completed against the named non-production Shopify Basic store. This does not prove production deployment readiness.
- **Partially live-validated:** a named subset completed against the staging store, while the remaining lifecycle or customer surface is still pending.
- **Implemented; partially live-proven:** the complete intended code path exists and a named subset has live evidence, while representative live scenarios remain.
- **Implemented; not yet live-proven:** the complete intended code path and automated tests exist, but the target-store lifecycle has not been exercised.
- **Implemented with policy limits:** the usable implementation deliberately exposes a narrower verification or provider policy than a fully provider-attested integration; the limitation is part of the product contract.
- **Wired core:** implemented and connected to an authenticated API, webhook, or scheduled worker. Deployment, operations, or live-flow validation is still required.
- **Core only:** domain code and tests exist, but no complete merchant/customer trigger invokes it.
- **Built only:** the extension or UI builds, but deployment and live shopper validation have not completed.
- **Missing:** no usable implementation was found.
- **Not yet live-validated:** a qualifier for code that has not completed the relevant target-store flow.
- **Deferred:** intentionally excluded from the current product scope.

## Reuse of existing Weletic Room technology

Weletic Room is a strong base for this module:

- **Workspaces and connected Shopify stores** provide the tenant boundary. Loyalty records are store-scoped and admin routes derive the store from the authenticated workspace.
- **Links** can create shopper referral URLs without turning shoppers into affiliate Partners.
- **Groups and Partners** remain affiliate concepts. They should not be reused as loyalty accounts because doing so would mix points liabilities with commission/payout identities.
- **Conditions** can be reused for earning eligibility and reward targeting, but loyalty needs its own typed validation and store-scoped evaluation.
- **Commerce ingestion** supplies canonical orders, lines, refunds, base-currency amounts, and webhook idempotency.
- **RBAC, cron authentication, Shopify sessions, and extensions** provide the operational shell around the loyalty domain.
