# S21 first recorded earn accounts candidate — September 24, 2026

This is a **partial analytics implementation candidate**, not a lifetime customer cohort or installed release acceptance. It counts distinct loyalty accounts with a positive retained `EARN_ORDER`, `EARN_REFERRAL`, `EARN_BONUS` or `TIER_BONUS` ledger entry in each UTC month of an explicitly selected interval. Imports, backfill corrections, manual adjustments and non-positive entries do not establish an earn. An account is “first recorded” in a month only if its earliest retained qualifying earn falls inside the selected instants and that month; otherwise an earning account is “returning.” An account appears in one cohort per month, even if it earns several times.

The service starts from distinct accounts active in the requested interval and checks account-scoped history for a qualifying earlier earn. The existing `(accountId, createdAt)` index can support this predicate; the provider execution plan still needs verification. Thus an earlier earn on the same UTC month but before the selected start makes a later in-range earn returning. Both dates are required and the range is capped at 366 UTC days. Empty months appear as zero counts. The report never returns account or shopper identifiers.

The coverage marker `retained_qualifying_ledger_accounts_only` is material. Missing pre-Weletic history, erased accounts and a shopper with multiple accounts cannot be reconstructed from retained ledger entries. “First recorded” must not be presented as the shopper's first lifetime earn. Reversed/refunded grants remain recorded earns. The UI states these limits in EN/JA/VI.

The read inherits signed Shopify merchant authentication, actor-derived store scope, a repeatable-read snapshot and owner-only CSV/JSON exports. No new table or migration is introduced; the provider query plan and source coverage still need installed acceptance.

Local evidence: 40 focused service/contract/UI tests passed, including large exact count strings, range states, quiet months, inconsistent aggregates and EN/JA/VI display. An isolated MySQL 8.0 fixture checks a first earn before the range, a first earn within it, repeated earning in a later month and cross-store exclusion; direct SQL confirms the accounts' earliest qualifying dates. The fixture schema, principal and container were removed after the check.
